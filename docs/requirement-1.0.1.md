## 1. 背景与目标

当前 V1.0.0 界面功能齐全，但存在两类问题：

1. **功能缺口**：缺少设备录屏能力。排查 UI 问题时只能连续截图，效率低。
2. **布局问题**：
   - 「文件与设备操作」卡片把 4 个不相关操作平铺（截图 / 安装 APK / 拉取 / 推送），截图与文件传输混杂；
   - 应用列表（app-list）纵向空间被挤占，min-height 仅 100px（约 2 行可见），浏览应用需频繁滚动。

V1.0.1 目标：**新增录屏、重组 UI 分组、把释放的纵向空间让给应用列表**，不改变任何既有功能行为。

## 3. 功能需求：设备录屏（REQ-01）

### 3.1 功能描述

用户选中设备后，一键开始录制设备屏幕，再次点击结束录制，视频自动保存到本机。

### 3.2 技术方案（两段式）

基于 `adb shell screenrecord`。该命令无法像 screencap 一样经 exec-out 直接取回视频流，采用**录制 → 回传**两段式：

**阶段一：录制**
```
adb -s <serial> shell screenrecord --time-limit 180 /sdcard/adbhelper_record_<yyyyMMdd_HHmmss>.mp4
```
- 进程由会话持有，`--time-limit 180` 兜底（screenrecord 硬上限 3 分钟，到时自动结束并正常生成完整文件）
- 录制期间前端每秒显示 mm:ss 计时 + 红点闪烁

**阶段二：停止 + 回传**
1. 停止：向设备端 screenrecord 进程发送 SIGINT（等效用户按 q），生成完整 mp4 索引（moov box）
2. 回传：`adb -s <serial> pull /sdcard/adbhelper_record_xxx.mp4 <本地目录>`
3. 校验：校验本地文件头部含 `ftyp` box（有效 mp4 标志），失败则删除本地坏文件 + 清理设备端残留，报错提示重试
4. 清理：成功回传后删除设备端临时文件

**停止信号方案（实现时验证后固定）**，按优先级尝试：
1. `adb -s <serial> shell pkill -l2 -f screenrecord`（toybox pkill，部分旧系统无 pkill）
2. `adb -s <serial> shell killall -s INT screenrecord`（toybox killall）
3. 兜底：`adb -s <serial> shell "kill -INT $(pidof screenrecord)"`（pidof 最通用）

> 实现第一天先在真机验证三种命令的可用性，固定后写入交接文档，单测按固定方案写。

### 3.3 交互设计

| 元素 | 规格 |
|------|------|
| 按钮 | 「开始录屏」⇄「停止录屏」同位切换；录制中按钮变红 |
| 状态 | 录制中：红点闪烁 + mm:ss 计时；停止后反馈本地文件完整路径 |
| 目录 | 录屏目录独立选择器；默认程序目录下 `videos/`；选择后记忆（与截图目录同机制） |
| 互斥 | 录屏会话与一键日志抓取**互斥**（同一 adb shell 通道抢占风险），UI 联动置灰；与实时日志/命令行模式不互斥 |
| 切换设备 | 录制中切换设备 → 弹窗确认「停止当前录屏并切换？」 |
| 设备断开 | 自动结束会话，尽力回传；失败给出明确报错 |
| 应用退出 | shutdown 钩子自动停止并尽力回传（无法回传时本地报错，设备端残留下次录屏前清理） |
| 兼容性 | screenrecord 需 Android 4.4+；低版本设备点开始时报错提示 |

### 3.4 约束与已知限制

- 单段录制最长 3 分钟（Android 硬限制），到时自动停止并提示「已达最长时长，自动停止」
- 录屏期间设备端会有系统通知/顶部提示条（系统行为，工具不干预）
- 音频不录制（screenrecord 本身不支持）

## 4. UI 重构需求（REQ-02/03/04）

### 4.1 布局调整（v5 定稿，2026-09-18 评审通过）

**改造前（V1.0.0）**：
```
┌─────────────────────────────────────────┐
│ 设备连接          │ 应用管理（列表 ~2 行）│
├─────────────────────────────────────────┤
│ 文件与设备操作                           │
│ [截图] [安装APK] [拉取] [推送]  ← 4 卡平铺 │
├─────────────────────────────────────────┤
│ 日志抓取                                 │
├─────────────────────────────────────────┤
│ 底部三模式面板                            │
└─────────────────────────────────────────┘
```

**改造后（V1.0.1 · v5 定稿）**：左列三张轻量操作卡纵排，右列应用管理独占全高
```
┌─────────────────────────┬───────────────────────────────┐
│ 设备连接                 │ 应用管理                       │
│ [IP][端口][连接][刷新]    │ [过滤][仅第三方][查询应用]       │
│ [查看设备与历史]          │ ┌───────────────────────────┐ │
│ [设备下拉框]              │ │ 应用列表（独占右列全高      │ │
├─────────────────────────┤ │    可见 10 行+）            │ │
│ 屏幕采集 [📷截图|🎥录屏]  │ │                           │ │
│ [目录][选目录][一键截图]   │ └───────────────────────────┘ │
├─────────────────────────┤ [APK路径][选文件][安装(-r覆盖)] │
│ 文件传输 [⬇️拉取|⬆️推送]  │                               │
│ [设备路径][开始拉取]       │                               │
│ [本机目录][选目录]         │                               │
├─────────────────────────┴───────────────────────────────┤
│ 日志抓取  [开始抓取][结束抓取][清空缓冲][目录][选目录]        │
├──────────────────────────────────────────────────────────┤
│ 底部三模式面板（操作反馈 / 命令行 / 实时日志）                │
└──────────────────────────────────────────────────────────┘
```

布局要点（评审定稿记录）：
- 左右两列等宽（1fr:1fr）；左列设备连接/屏幕采集/文件传输三卡均分列高
- 右列应用管理单卡独占整列高度，应用列表 `flex:1` 吃满剩余空间
- 共用组件：屏幕采集卡内 `[截图|录屏]` 分段切换、文件传输卡内 `[拉取|推送]`
  分段切换——同一时刻只渲染当前模式的控件（用户明确要求，否决了并排堆叠方案）
- 控件全部横排（用户否决了 4 卡平铺窄卡的竖排控件方案）

### 4.2 卡片归组（v5 定稿）

| 位置 | 卡片 | 成员与说明 |
|------|------|------------|
| 左列·上 | 设备连接 | 原卡整体迁入，交互不变 |
| 左列·中 | 屏幕采集 | 截图 + 录屏（新增），分段切换共用一卡；录屏目录独立选择（默认 videos/），截图维持 screenshots/ |
| 左列·下 | 文件传输 | 拉取 + 推送，分段切换共用一卡，原 pull/push 交互不变 |
| 右列（独占全高） | 应用管理 | 查询/列表 + **安装 APK 移入本卡底部**（语义闭环：查应用→管应用→装应用） |
| 通栏 | 日志抓取 | 维持独立卡片，仅增加与录屏的互斥置灰联动 |

原「文件与设备操作」卡片取消。

### 4.3 应用列表扩空间（REQ-04）

约束：窗口尺寸不变。v5 布局下右列整列归应用管理，列表收益最大化。

1. 右列独占全高 → 应用列表实际高度约 400px+（旧版约 100px），**可见行数 2 行 → 10 行+**
2. 释放空间来源：原 4 卡平铺行（约 150px）+ 安装 APK 并入应用管理卡后省掉的卡片行距
3. `.app-list` 的 `min-height` 从 100px → **220px**（极端小窗兜底）
4. 列表行高紧凑化：行 padding 8px → 6px，单行约 43px → 38px
5. 非全屏极端场景仍走整页滚动兜底（现有机制，不变）

## 5. 验收标准

### 5.1 录屏功能

| 编号 | 验收项 |
|------|--------|
| AC-01 | 点「开始录屏」→ 按钮变「停止录屏」红色 + 红点闪烁 + mm:ss 计时；点停止 → mp4 落盘可播放，反馈完整路径 |
| AC-02 | 连续录满 3 分钟：自动停止 + 提示 + 文件完整可播放 |
| AC-03 | 录制中切换设备：弹窗确认 → 停止 + 回传 + 反馈，无孤儿文件 |
| AC-04 | 录制中设备断开：自动停止 + 尽力回传 + 明确反馈 |
| AC-05 | 录制中退出应用：自动停止尽力回传；无法回传时下次启动/下次录屏前清理设备端残留 |
| AC-06 | 目录自定义：默认 `videos/`，选择后跨会话记忆 |
| AC-07 | 互斥联动：录屏中「开始抓取」按钮置灰（反之亦然），实时日志/命令行不受影响 |
| AC-08 | screenrecord 不存在（Android < 4.4）：点开始即报可理解错误 |
| AC-09 | pull 回传失败：清理设备端残留 + 明确报错 |
| AC-10 | 停止命令三方案均不可用（极老设备）：超时兜底停止 + 报错提示 |

### 5.2 UI 重构

| 编号 | 验收项 |
|------|--------|
| UI-01 | 左列三卡（设备连接/屏幕采集/文件传输）+ 右列应用管理独占全高的 v5 布局 |
| UI-02 | 屏幕采集卡 `[截图|录屏]`、文件传输卡 `[拉取|推送]` 分段切换，同一时刻只显示当前模式控件 |
| UI-03 | 安装 APK 移入应用管理卡底部 |
| UI-04 | 应用列表 min-height ≥ 220px，1080p 默认窗口实测可见 ≥ 10 行（旧版约 2 行） |
| UI-05 | 应用列表高度随窗口拉伸增大（右列 flex 布局），所有旧功能入口可发现，各操作语义与反馈行为不变 |

### 5.3 质量要求（对齐仓库提交流程）

- 后端录屏逻辑单测覆盖：文件名时间戳生成、停止命令拼装（按固定方案）、mp4 `ftyp` 头校验、会话状态机（Idle/Recording/Stopping/Pulling）
- blackbox stubadb 增加 screenrecord / pull 行为模拟，离线黑盒可跑
- `check.bat` 全绿（vet / fmt / build / test / wails build）
- 真机手工走查全部验收标准，结果记入交接文档
