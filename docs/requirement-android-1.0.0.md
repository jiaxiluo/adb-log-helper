## 1. 背景与目标

桌面版 adb-log-helper 已在用，但现场场景（客户现场 / 机房 / 出差）手边往往只有手机。
手机上需要的不是"日常运维工作台"，而是**应急工具**，只做两件事：

1. 给电视/盒子推一个新 APK
2. 出问题时抓一份日志，**当场发回微信群**

V1.0.0 目标：一个原生安卓 App，通过 Wi-Fi 连接电视/盒子（ADB 5555），完成上述两个动作，
全程无需电脑、无需命令行。功能是桌面版的精简子集 + 手机特有的"分享"闭环。

### 与桌面版的关系

- 独立 App、独立代码（Kotlin），**不与桌面版共用代码**
- 仅沿用品牌与"两键式"交互理念；界面为手机竖屏全新设计

## 3. 功能需求

### 3.1 REQ-A1 设备连接

**描述**：输入电视/盒子的 IP（可带 `:端口`，缺省 5555）连接；显示在线状态；记住连过的设备。

**技术要点**：
- 底层：`adb connect <ip>:5555`，连接后 `adb devices` + `getprop`（型号/品牌/安卓版本）确认
- 首次连接电视端弹"允许 USB 调试"授权（勾选始终允许后下次免确认），与桌面版体验一致
- 历史记录存本地（IP + 型号 + 最近连接时间），点击直连；可删除
- 断线检测：操作前校验设备在线，不在线给出明确提示并引导重连

**交互设计**：

| 元素 | 规格 |
|------|------|
| 连接输入 | IP 输入框 + 「连接」按钮；支持回车触发 |
| 状态灯 | 绿=在线；灰=未连接；连接中转圈 |
| 已连接卡 | 状态灯 + IP + 型号 · 安卓版本 + 「断开」按钮 |
| 历史列表 | 每行：IP + 型号 + 最近时间，行尾 × 删除；点击即连 |
| 置灰联动 | 未连接时「安装/抓日志」两卡置灰，提示"请先连接设备" |

### 3.2 REQ-A2 安装 APK

**描述**：选手机里的 APK 文件，一键安装到已连接设备，覆盖安装（`-r`，保留应用数据）。

**技术要点**：
- 文件选择用系统选择器（SAF）；因 adb 进程读不了 `content://`，
  先拷贝到 App 缓存目录再执行 `adb -s <serial> install -r <本地文件>`
- `adb install` 自带 `Streaming...` 进度输出，解析后显示（无法精确到百分比时显示"传输中/安装中"两段）
- 结束后自动删除缓存目录副本，不占手机空间
- 失败原因翻译成人话（对照桌面版已有的错误映射表迁移）：

| 设备端输出 | 界面提示 |
|------|------|
| INSTALL_FAILED_VERSION_DOWNGRADE | 安装失败：新包版本号比设备上的低，需先卸载旧版 |
| INSTALL_FAILED_UPDATE_INCOMPATIBLE | 安装失败：签名不一致，需先卸载原应用 |
| INSTALL_FAILED_INSUFFICIENT_STORAGE | 安装失败：设备存储空间不足 |
| INSTALL_FAILED_OLDER_SDK | 安装失败：设备安卓版本过低，不满足此 APK 要求 |
| Success | 安装成功 |

**交互设计**：

| 元素 | 规格 |
|------|------|
| 主按钮 | 「选择 APK 安装」；选完显示文件名 + 大小 → 「开始安装」 |
| 安装中 | 进度/阶段提示（传输中 → 安装中），按钮禁用 |
| 结果 | ✓ 成功（显示包名）；✗ 失败（中文原因 + 「重试」/「换个文件」） |

### 3.3 REQ-A3 一键抓日志 + 分享

**描述**：两键式抓取全量 logcat，存手机文件；结束后一键分享出去；期间可退后台/息屏继续抓。

**技术要点**：
- 底层：长驻子进程 `adb -s <serial> logcat -v time`，stdout 逐行写入手机文件
  `logs/<设备IP>/adb_log_<yyyyMMdd_HHmmss>.log`（命名与桌面版一致）
- **前台服务保活**：抓取在 Android 前台服务中运行，通知栏常驻显示（计时 + 已抓大小），
  息屏/退 App 不中断；Android 14+ 按规范声明 `foregroundServiceType`
- 结束 = 停止子进程 + 关闭文件；结束后展示文件卡（文件名/大小/时长）
- 分享：`FileProvider` 拉起系统分享面板（微信/钉钉/QQ 直接发）
- 互斥：开始抓取后连接断开 → 自动结束并提示；与安装操作共用 adb server，无冲突
- 设备端残留：杀掉抓取进程后确认设备端 logcat 是否残留（M1 验证项，残留则补清理动作）

**交互设计**：

| 元素 | 规格 |
|------|------|
| 就绪态 | 「开始抓取」大按钮 + 一行说明（存哪、可后台） |
| 抓取中 | 红点闪烁 + mm:ss 计时 + 已抓大小实时增长；「结束并分享」按钮变红 |
| 后台提示 | 文案："可退出 App / 息屏，后台继续抓取（通知栏可见）" |
| 结果态 | 文件卡（文件名 + 大小 + 时长）+ 「分享」+「再抓一份」 |
| 分享 | 拉起系统分享面板（原型中以底部弹出模拟） |

## 4. 技术方案

### 4.1 总体架构

- **原生安卓**：Kotlin + Jetpack Compose（Material 3），单 Activity，极简（3 张卡片一屏）
- 不复用桌面版 Wails 前端 —— 功能只剩两个，原生写界面更简单，且文件选择器/分享/前台服务
  全是原生 API，走 WebView 反而要加桥接层
- minSdk 26（Android 8.0，覆盖 98%+ 设备）/ targetSdk 35
- 预计体积 ~8-10MB（大头是 adb 二进制）

### 4.2 ADB 路线（核心决策，M1 验证）

**主案：随 App 打包 adb 二进制（LADB 已验证此路线可行）**

- Android 10+ 禁止 App 执行自身可写目录里的文件 → 把 arm64 的 adb 二进制
  命名为 `libadb.so` 放入 `jniLibs/`，从 `nativeLibraryDir`（只读）执行
- `HOME` 环境变量指向 App 私有目录（`filesDir/.adb`），adb 密钥持久化在此
- 只打包 arm64-v8a（现行手机基本全 arm64；后续有需求再补 armeabi-v7a）
- 二进制来源（按优先级调研）：社区静态编译版 / 从 Termux android-tools 包提取 /
  AOSP+NDK 自编译（工作量大，不作首选）

**备选案：纯 Kotlin 实现 ADB 协议（AOSP adblib 或等价开源库）**

- 仅当 M1 验证二进制路线失败时切换；install = sync push + `pm install`，logcat = shell 流

### 4.3 里程碑

| 阶段 | 内容 | 出口标准 |
|------|------|------|
| M1 技术验证（壳工程） | 最小工程：exec `libadb.so` → `connect` 电视 → `install` 一个 APK → `logcat` 落文件，四步真机跑通 | 四步全通 = 路线确认；任一步失败 → 评估备选案再向你汇报 |
| M2 设备连接 | 连接/状态/历史（REQ-A1） | 真机连电视全流程可用 |
| M3 安装 APK | 选文件/安装/错误中文化（REQ-A2） | 现场真实 APK 安装成功 |
| M4 抓日志+分享 | 前台服务/通知/分享（REQ-A3） | 息屏 10 分钟日志完整、可发微信 |
| M5 打磨发布 | 边界（断线/超时/重连）+ 签名出正式 APK | 侧载安装可用，交接文档同步 |

> M1 是风险关门点：通过前不写正式界面代码。

### 4.4 开发与分发

- 工程位置：`tools/adb-log-helper/android/`（源码），产物 APK 发布到 `adb-helper/` 目录
- 本机需首次安装：JDK 17 + Android SDK（commandline-tools，磁盘约 5GB）
- 签名：本地生成自签 keystore **妥善保管**（丢失则后续新版无法覆盖安装，只能卸载重装）
- 分发：直接发 APK 侧载（手机需允许"安装未知来源应用"）

### 4.5 风险清单

| 风险 | 影响 | 对策 |
|------|------|------|
| adb 二进制在部分机型上跑不起来 | 路线失败 | M1 真机优先验证；备选纯协议方案兜底 |
| 杀掉抓取进程后设备端 logcat 残留 | 设备端多进程堆积 | M1 验证，残留则结束时补清理命令 |
| 厂商 ROM 杀后台激进（息屏断网） | 息屏抓取中断 | 前台服务 + 引导用户加电池优化白名单 |
| 电视端 5555 未开/防火墙拦截 | 连不上 | 界面报错提示 + 操作手册排查步骤 |
